# ADR-0003：合并 pixel/file 两种插件、取消实时预览

- **状态**：Accepted
- **日期**：2026-10-11

## 背景

早期设计把插件分成两类:

- **`kind:"pixel"`** — 纯像素变换(同尺寸、同格式),预期跑在**常驻 worker**、宿主预解码底图、支持**实时预览**(拖滑块即时刷新)。
- **`kind:"file"`** — 路径进、文件出,跑在子进程。

讨论中发现两个问题:

1. **应用模型被澄清**:"启动选一张底图当蓝本"是误解。真实模型是**工具箱**——启动加载已安装插件,**进入插件后**才选择该插件声明的输入文件。
2. **实时预览与并行/批量冲突**:部分方法需要批量并行处理,而"实时预览"要求宿主持有常驻像素缓冲、逐参数回调 worker,这套 worker 层**既受限又复杂**。同时,这些处理要么很快(实时预览无价值)、要么很慢(实时预览体验差)。

## 决策

- **删除实时预览**与 `kind` 分流;**合并**为单一"路径契约"子进程模型(即原 `file` 家族的契约,见 ADR-0002)。
- **保留"手动预览"**:运行一次 → 窗口显示结果 → 不点"保存"不落盘。
- manifest **移除 `kind`** 字段。
- **批量成为一等能力**:`files` 参数 = 批量轴,宿主起 N 个并行子进程;多个 `files` 参数按**序号 zip 配对**。

## 后果

- **收益**:宿主大幅简化——删除 worker 层、宿主预解码、参数防抖、kind 分流整套复杂度;批量化/并行成为常规能力。
- **代价**:失去"拖拽参数即时看效果"的交互体验(经权衡,认为不值得;慢操作下本就不适)。
- **依赖**:本决定与 ADR-0001(Electron)、ADR-0002(子进程契约)共同定义当前架构。
